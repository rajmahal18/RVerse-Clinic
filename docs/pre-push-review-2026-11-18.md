# Pre-push review — 18 November 2026

Reviewed the pending patient workflow, medical forms, admin archive/restore actions, Prisma filters, and additive migrations. Five findings were resolved before handoff:

1. **Medicine return could use a stale quantity.** An archive action read the request before a concurrent completed-visit correction committed. Archive/restore now locks the parent visit before the medicine row, then re-reads the request. Stock returns use the committed quantity and status. The lock order matches clinical corrections. A regression test simulates a quantity correction while the action waits for the row lock.
2. **Draft restoration could uncheck a locked service.** Native input restoration overwrote the recorded checkbox, and the React change handler could remove its state despite a prevented click. Locked controls are skipped during native restoration and their change handler preserves the recorded selection. Browser tests cover an old draft missing a recorded service and a newer cached draft containing a removed service.
3. **Stale forms could revive removed services.** Child archive/restore did not change the parent visit version. These mutations now update that version; active visit forms submit an optional version checked under the visit lock. Existing completed-visit version checks also see child changes. The draft API identifies removed service types, and restoration filters them from both server and browser-cached drafts. Legacy form callers without a version remain compatible.
4. **Voided records could retain a patient in module lists.** Vaccination and scheduled-follow-up membership predicates did not exclude archived children, even though the displayed child records were filtered. The membership predicates now require active records. Tests verify that an exclusively voided vaccination or follow-up produces no patient-list row.
5. **Archiving a batch could erase historical stock-report totals.** Historical reports queried the normal active inventory list, dropping old movements from totals when a batch was archived. Historical stock and request-frequency reports explicitly include archived batches. Normal inventory and request selectors remain filtered. A regression test compares stock totals before and after archiving a batch.

Validation includes TypeScript, production build, archive/stock/permission tests, clinical and migration checks, multi-medicine tests, and responsive browser interactions. Transaction tests use an isolated in-memory adapter with simulated interleaving; SQL migrations are checked with isolated PostgreSQL/PGlite. This does not replace a deployment smoke test against the actual target database.

Stage the new source files, regression scripts, documentation, and **both** migration folders together. Apply migrations before starting the updated app. No live migrations or pushes were performed during review.
